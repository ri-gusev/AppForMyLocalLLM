# День 29: оптимизация локальной Qwen

Измерения выполнены 10 октября 2026 года. Кейс — краткие ответы по
документам и C++-коду с подтверждающими источниками. Модель qwen3:8b,
квантование Q4_K_M, эмбеддинги bge-m3. Облачная генерация не использовалась.

## Итоговый профиль

- num_ctx=8192 вместо 16384; num_predict=512 вместо отсутствующего явного лимита.
- temperature=0, think=false. Temperature 0.2 проверена отдельно; оставлена 0.
- Более строгий русский RAG-промпт: краткость, источник после факта,
  точные единицы и отказ от догадок при недостатке доказательств.
- История в памяти ограничена восемью обменами; в запрос включаются только
  полные последние пары, которые помещаются вместе с вопросом, документами
  и резервом ответа. Обычный чат работает без retrieval и RAG-промпта.
- Убираются повторяющиеся и полностью вложенные фрагменты; разные факты
  сохраняются. Перекрывающийся текст границ по возможности удаляется.
- Документы сокращаются на границах UTF-8 до общего бюджета. В интерфейсе
  отображаются только фактически переданные источники.
- Обрезание ответа, сокращение контекста и старой истории явно отмечаются.
- Номера ссылок нормализуются и проверяются на существование. Содержательная
  правильность каждого утверждения и ссылки автоматически не доказана.

Подробности бюджета: [профиль генерации](../docs/generation-profile.md).

## Скорость и ресурсы

Три одинаковых вопроса по два повтора, каждый в отдельном диалоге.
В каждом из трёх финальных профилей 6/6 запросов завершились успешно.

| Показатель | До | После, T=0 | После, T=0.2 |
|---|---:|---:|---:|
| Среднее время поиска | 5.72 с | 6.19 с | 6.10 с |
| Среднее время генерации | 13.82 с | 10.06 с | 10.03 с |
| Среднее время всего | 19.54 с | 16.25 с | 16.13 с |
| Пик суммарного working set Ollama/llama | 2093.35 МБ | 1199.11 МБ | 1200.93 МБ |
| Пик общей занятой VRAM всех GPU | 6133.00 МБ | 6035.00 МБ | 6035.00 МБ |


Средняя генерация уменьшилась на 27.2%,
полное время — на 16.9%, пик RAM — на
42.7%. Поиск в этом прогоне стал немного медленнее;
он включает эмбеддинг, чтение SQLite и подготовку контекста.

RAM измерялась как сумма WorkingSet64 процессов с именами ollama/llama,
а не отдельное выделение памяти конкретной модели. VRAM — суммарная
занятость видеокарт из nvidia-smi, включая другие приложения.
Замеры не изолированы от системы, не являются независимыми холодными
запусками и не доказывают причинный эффект каждого отдельного изменения.
Разница VRAM небольшая; считать её гарантированным выигрышем нельзя.

## Качество и повторяемость

Проверены факты по сохранённым фрагментам:

| Вопрос | До | Финальный профиль |
|---|---|---|
| Модель embedTexts | bge-m3, верно | bge-m3, верно, ссылка [4] |
| Лимит validSearchRequest | 16000 **символов**, неверные единицы | 16000 **байт**, верно, ссылка [1] |
| Алгоритм rankVectors | Косинусное сходство, но ссылка на заголовок вместо реализации | Косинусное сходство, ссылка [2] на реализацию |

У T=0 совпали дословно 3/3 пары ответов, у T=0.2 —
1/3. У T=0.2 ответы по проверенным фактам тоже корректны,
заметного выигрыша скорости нет, встречается лишнее слово «Факт» возле ссылки.
Поэтому основной профиль оставлен T=0.

Первый английский вариант усиленного промпта не исправил единицы и
генерировал ссылки вида [id:1]. Эти неудачные промежуточные прогоны
сохранены в day29-iteration1*.json. Итоговый русский промпт содержит
явный пример std::string::size(): лимит измеряется в байтах.
Шаблон адаптировался по этим известным ошибкам; отложенной выборки нет.
Нельзя переносить результат трёх вопросов на качество всех ответов.

В сыром day29-after.json прежняя проверка английского слова "cosine"
дала 4/6: два правильных ответа использовали русское «косинусной».
Сырые результаты не переписаны. Для следующих запусков проверка принимает
оба варианта. Проверка ключевых слов в любом случае не заменяет проверку фактов.

## Проверки

- CTest: бюджет входа и ответа, полные пары истории, слишком длинный вопрос,
  UTF-8 контекст, дубликаты, сохранение разных фактов, предупреждение об
  обрезании, нормализация ссылок и сохранение кода; тесты индексации и извлечения.
- chat_modes_live: переключатель, обычный чат без базы RAG, сохранение истории,
  блокировка переключателя во время запроса и возврат в RAG.
- truncation_live: реальный ответ Ollama по лимиту 512 токенов и отображение
  предупреждения; результат в day29-truncation.json.
- Windows-приложение собрано. Визуальная проверка рабочего стола не проводилась.

## Артефакты

- day29-before.json — исходные ответы и время.
- day29-after.json — итоговый профиль T=0, токены и источники.
- day29-temperature02.json — тот же итоговый профиль T=0.2.
- *.resources.json — сырые измерения RAM/VRAM с временными метками.

Новая сборка: `build/local_agent_optimized.exe`. Она находится рядом с прежней
и использует ту же папку данных, включая добавленные документы.
Открытая прежняя программа не завершалась автоматически.
