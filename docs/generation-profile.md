# Профиль генерации — День 29

В обоих режимах: `num_ctx=8192`, `num_predict=512`, `temperature=0`,
`think=false`. Квантование Q4_K_M и эмбеддинги bge-m3 сохранены.

RAG-промпт требует краткого ответа на языке вопроса, ссылки возле каждого
подтверждённого факта, точных единиц и сообщения о нехватке доказательств.
Декларация функции не считается доказательством её поведения.
При отключённом RAG системный промпт и документы не передаются.

Оценка бюджета до запроса консервативная: число UTF-8-байтов с запасом на
роли и шаблон используется как верхняя оценка для byte-level BPE Qwen.
Это не точный токенизатор. Из окна резервируются 512 токенов на ответ
и 256 на шаблон. Для истории по возможности остаётся ещё 1024 байта.
В памяти сохраняются до восьми обменов. В запрос попадают только последние
полные пары, которые помещаются. Текущий вопрос не обрезается: если он
слишком большой, приложение просит сократить его. Ответные счётчики Ollama
также проверяются на превышение окна. Это может исключить часть текста,
которая поместилась бы при точной токенизации.

RAG удаляет одинаковые после нормализации пробелов и полностью вложенные
фрагменты. Похожие тексты с разными фактами сохраняются. Перекрытие на
границах выбранных фрагментов одного файла по возможности убирается.
Фрагменты ограничены 2200 байтами и общим бюджетом; обрезание сохраняет
границы UTF-8. Источники в интерфейсе соответствуют фактически переданным
текстам. Сокращение документов и исключение старой истории отмечаются.

Если Ollama сообщает завершение по лимиту, показывается предупреждение
«Ответ обрезан: достигнут лимит 512 токенов». Автоматическое продолжение
не запускается; уточните вопрос или разбейте его на части.

Счётчики токенов, длительность генерации и причина завершения берутся из
[ответа Ollama API](https://docs.ollama.com/api/chat).
Ссылки `[id:2]` приводятся к `[2]`, неизвестные номера отмечаются
предупреждением. Код в backtick-блоках и inline-коде не изменяется.
Автоматическая проверка достоверности и соответствия факта цитате не добавлена:
более строгий промпт не гарантирует отсутствия ошибок.

## Повторение измерений

```powershell
cmake --build --preset mingw-debug --target rag_eval
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/measure-run.ps1 -Executable build/rag_eval.exe -Report reports/day29-after.json
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/measure-run.ps1 -Executable build/rag_eval.exe -Report reports/day29-temperature02.json -Temperature 0.2
```

Измерения и ограничения сравнения находятся в `reports/day29-summary.md`.
Обычный CTest не запускает генерацию. Проверка переключателя с реальной
моделью выполняется отдельно через цель `chat_modes_live`.
