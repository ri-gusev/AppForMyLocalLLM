# LocalAgent

Windows-приложение на C++17 с базовым графическим чатом и локальной моделью
`qwen3:8b` через Ollama (`localhost:11434/api/chat`). Облачные модели
и API-ключи не используются.

Введите сообщение и нажмите Enter или «Отправить». Shift+Enter добавляет
новую строку. Ответы и история отображаются в верхней части окна.
Во время запроса окно остаётся отзывчивым; следующая отправка доступна
после ответа. Ошибка показывается в чате, после неё можно повторить запрос.
Пустые сообщения пропускаются. Для выхода закройте окно.

Переключатель RAG вверху окна включает и выключает поиск по документам.
По умолчанию RAG включён. При выключении сообщения отправляются прямо
в Qwen с историей диалога, без эмбеддингов, чтения индекса и ограничивающего
ответы системного промпта RAG. История сохраняется при смене режима, поэтому
прежние реплики и ответы остаются частью разговора. В обычном режиме
источники и время поиска не показываются. Переключатель недоступен во время
запроса или индексации; файлы можно добавлять при любом режиме.

Кнопка «Добавить файлы» открывает выбор TXT, Markdown (.md), PDF и DOCX.
Можно выбрать несколько файлов. После выбора сразу запускается локальная
индексация, прогресс отображается внизу окна. По её завершении задавайте
вопросы по добавленным документам.

История успешных сообщений и ответов передаётся модели при каждом запросе
и хранится в памяти до завершения программы. Длина разговора ограничена
контекстным окном модели; автоматического сокращения истории пока нет.

## Сборка и запуск

Нужны CMake 3.20+, MinGW-w64 (g++ и mingw32-make в PATH), запущенный Ollama
и установленные модели `qwen3:8b`, `bge-m3`. Для сборки также нужны
заголовок и библиотека SQLite3 (в MSYS2 UCRT64: `mingw-w64-ucrt-x86_64-sqlite3`).
Для извлечения PDF/DOCX нужен установленный Python 3.9+; библиотека `pypdf`
уже включена в проект. TXT и Markdown не требуют Python.

```powershell
cmake --preset mingw-debug
cmake --build --preset mingw-debug
ctest --test-dir build --output-on-failure
.\build\local_agent.exe
```

## Локальный RAG — День 28

Перед генерацией вопрос преобразуется в эмбеддинг через локальный
Ollama `/api/embed` с моделью `bge-m3`. Затем C++ читает SQLite-индекс,
считает косинусное сходство, отбирает 10 кандидатов, применяет порог 0.45
и ту же ограниченную эвристику ранжирования из исходного проекта.
До 4 фрагментов передаются локальной Qwen. Параметры находятся
в `config/rag_config.json`.

`data/document_index.db` — снимок существующего индекса Недели 6 из
`AICourse/AIAgentsCourse`: 596 структурных фрагментов, размерность 1024.
Это снимок документов и кода на момент индексации, а не текущие исходники.
Исходный проект не изменяется. Чтобы обновить исходный индекс, создайте его
в исходном проекте с `bge-m3`, перенесите согласованный SQLite-снимок
и пересоберите приложение.

### Добавление документов и семантическая индексация

Файлы читаются локально и делятся на фрагменты до 2200 байт UTF-8
с перекрытием около 250 байт и предпочтением границ строк. Для каждого
фрагмента `bge-m3` вычисляет эмбеддинг. Новые фрагменты сохраняются
в отдельной базе `data/user_index.db` рядом с приложением; исходный индекс
остаётся доступен только для чтения. Семантический поиск по косинусному
сходству объединяет оба индекса. Добавленные документы доступны после
перезапуска; исходные файлы после индексации для поиска не нужны.

Повторный выбор того же полного пути обновляет документ без дубликатов.
Обновление фиксируется одной транзакцией после получения всех эмбеддингов.
При ошибке старые фрагменты сохраняются. В наборе файлов ошибка одного
документа не мешает обработке остальных. Во время индексации нельзя
запустить другую индексацию или отправить сообщение; окно остаётся отзывчивым.

Поддерживаются UTF-8, UTF-16 с BOM и Windows-1251 для TXT/MD. Максимальный
размер исходного файла — 10 МБ. PDF требует текстового слоя: OCR и
пароль для закрытых PDF не предусмотрены. DOCX извлекает текст абзацев
и таблиц основного документа. В источниках сохраняются номера страниц PDF
и строки извлечённого текста. Изображения в документах не индексируются.

Для PDF/DOCX CMake сохраняет путь к найденному Python в
`config/python_path.txt`; если этот путь недоступен, программа ищет
`python.exe` в PATH. При переносе на другой компьютер установите Python
и при необходимости обновите этот файл полным путём к интерпретатору.
Все вызовы извлечения и эмбеддингов выполняются локально.

В чате отображаются переданные фрагменты с именами источников и временем
поиска/генерации. Нумерацию цитат модель формирует сама; автоматической
проверки цитат и фактов нет. Если поиск не нашёл подходящих фрагментов,
приложение сообщает о нехватке данных без генерации. Ошибки индекса или
Ollama отображаются в чате без переключения на облако.

При сборке исходный индекс, `config/`, `scripts/` и `third_party/python/`
копируются рядом с `.exe`. Эти папки нужны при переносе приложения.
Пользовательский `data/user_index.db` сборка не перезаписывает.
Каталог приложения должен быть доступен для записи. Пути определяются от каталога `.exe`,
поэтому запуск не зависит от текущей папки терминала.

### Проверка качества, скорости и стабильности

```powershell
cmake --build --preset mingw-debug --target rag_eval
.\build\rag_eval.exe . reports/day28-local.json
```

Утилита выполняет три проверяемых вопроса по два раза, каждый в отдельном
диалоге. JSON-отчёт содержит ответы, тексты найденных фрагментов, оценки
сходства, время поиска/генерации и ошибки. Проверка качества по ожидаемому
термину является предварительной: полноту и обоснованность ответа нужно
оценивать по сохранённым фрагментам. Время первого запроса может включать
загрузку моделей; последующие запросы не являются независимыми холодными
запусками. Сравнение с облаком не выполнялось: облачный провайдер в этом
приложении не настроен.

## Структура

- `src/main.cpp` — запуск Windows-приложения.
- `include/chat_window.h`, `src/chat_window.cpp` — окно на Win32 и фоновая отправка.
- `include/ollama_client.h`, `src/ollama_client.cpp` — HTTP-клиент Ollama.
- `include/rag_chat.h`, `src/rag_chat.cpp` — поиск по индексу и генерация с контекстом.
- `include/document_import.h`, `src/document_import.cpp` — извлечение текста, фрагменты и сохранение индекса.
- `scripts/extract_document.py` — локальное чтение PDF/DOCX, адаптированное из исходного RAG-проекта.
- `third_party/python/` — pypdf 6.19.0 и лицензия BSD-3-Clause.
- `data/`, `config/` — готовый индекс и настройки RAG.
- `tools/rag_eval.cpp`, `reports/` — воспроизводимая оценка и результаты.
- `third_party/nlohmann/json.hpp` — JSON-библиотека версии 3.11.3 (MIT; лицензия внутри заголовка).
- `CMakeLists.txt`, `CMakePresets.json` — сборка.

HTTP работает через системный Windows WinHTTP. Зависимости при сборке
не скачиваются. Интерфейс поддерживает русский текст; HTTP использует UTF-8.
MinGW-сборка включает C++ runtime в исполняемый файл. Можно запускать
двойным щелчком по `build/local_agent.exe`, без консольного окна.

### Проверки загрузки

Обычный CTest проверяет извлечение, разделение текста, обновление без
дубликатов и сохранение старых данных при ошибке эмбеддингов или записи.
Проверка с настоящим Ollama запускается отдельно:

```powershell
python tests/document_extraction_tests.py scripts/extract_document.py build/document-fixtures
cmake --build --preset mingw-debug --target document_import_live
.\build\document_import_live.exe build build/document-fixtures
```

Она проверяет PDF/DOCX через C++-обработчик, сохранение эмбеддинга `bge-m3`,
семантический поиск после повторного открытия базы и ответ Qwen по
добавленному факту. Тестовые документы не добавляются в пользовательский индекс.
